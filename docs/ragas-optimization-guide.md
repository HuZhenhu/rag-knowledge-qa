# RAGAS 评测与优化指南

> 日期：2026-08-04
> 标准：RAGAS 评估框架（arXiv:2309.15217）
> 目标：用四维指标定位 RAG 系统瓶颈，数据驱动优化

---

## 一、RAGAS 四指标说明

RAGAS 从**检索**和**生成**两个维度评估 RAG 系统：

| 指标 | 评测什么 | 需要的输入 | 低分含义 |
|------|---------|-----------|---------|
| 忠实度 Faithfulness | 回答是否基于检索内容（有无幻觉）| 问题+回答+上下文 | LLM编造、上下文不完整 |
| 答案相关性 Answer Relevancy | 回答是否切题 | 问题+回答 | 回答跑题、答非所问 |
| 上下文精准度 Context Precision | 检索结果中相关chunk占比 | 问题+上下文 | 检索噪声多 |
| 上下文召回率 Context Recall | 答案信息是否检索全 | 问题+上下文+标准答案 | 检索遗漏关键信息 |

**推荐阈值**（来自 RAGAS 社区）：
- 忠实度 > 0.8
- 答案相关性 > 0.7
- 上下文精准度 > 0.6
- 上下文召回率 > 0.7

## 三、瓶颈诊断（2x2 矩阵）

用 RAGAS 的诊断矩阵归因问题环节：

```
              Context Recall（召回率）
           低             高
忠实度   ┌──────────┬──────────┐
高       │ ① 检索漏  │ ② 正常   │
（无幻觉）│   信息    │    ✓    │
        ├──────────┼──────────┤
低       │ ③ 检索漏  │ ④ 生成器  │
（有幻觉）│ + 生成差  │   问题   │
        └──────────┴──────────┘
```

**当前系统分布**：
- **001 RAG**：召回1.0 + 忠实1.0 → ② 正常 ✅
- **004 DeepSeek**：召回0.0 + 忠实0.58 → ③ 检索遗漏+生成差 ❌
- **008 BM25**：召回1.0 + 忠实1.0，但**精准度0.14** → 检索噪声大
- **030 部署**：召回0.0 + 忠实0.0 → ③ 严重问题

**三个主要瓶颈**：
1. **上下文精准度0.316**：检索返回7条，5条无关 → **检索召回过宽**
2. **上下文召回率0.589**：关键信息未检索到 → **检索覆盖不足**
3. **忠实度0.635**：部分回答幻觉 → **生成约束不够**

## 四、优化方案

### 优化1：提升上下文精准度（噪声问题）→ 优先

**问题**：检索返回7条，平均只有2-3条相关。

**方案**（按投入产出排序）：
| 方案 | 做法 | 预期效果 | 成本 |
|------|------|---------|------|
| 1a 提高相关性阈值 | RELEVANCE_THRESHOLD 0.45→0.55 | 过滤低相关chunk | 低 |
| 1b 降低top_k | 7→5，减少噪声chunk | 精准度提升 | 低 |
| 1c 重排序 | 启用 Reranker 精排 | 精准度大幅提升 | 中（需模型）|

**推荐**：先试 1a+1b（低成本），若不足再上 1c 重排序。

### 优化2：提升上下文召回率（遗漏问题）→ 次优先

**问题**：部分问题的关键信息没被检索到（如004 DeepSeek召回0.0）。

**方案**：
| 方案 | 做法 | 预期效果 | 成本 |
|------|------|---------|------|
| 2a 查询扩展 | 实现查询扩展，多子查询检索 | 召回提升 | 中 |
| 2b 多路检索 | 向量+BM25权重调整 | 召回提升 | 低 |
| 2c 降低精准度换召回 | 阈值降低到0.35 | 召回提升但噪声增 | 低 |

**权衡**：精准度和召回率是矛盾的。优化1提高精准度可能降召回，反之亦然。**需要平衡**——当前精准度0.32太低，先提精准度，同时用查询扩展补召回。

### 优化3：提升忠实度（幻觉问题）→ 生成层

**问题**：030部署忠实度0.0，可能编造了部署步骤。

**方案**：
| 方案 | 做法 | 预期效果 | 成本 |
|------|------|---------|------|
| 3a 降temperature | 0.1→0.0 | 减少编造 | 低 |
| 3b prompt约束 | 强调"只基于上下文" | 减少幻觉 | 低 |
| 3c 输出审查 | 生成后校验回答是否有依据 | 拦截幻觉 | 中 |

**注意**：之前 prompt 优化实验显示"过度结构化"会降分，需谨慎。先试3a（temperature降到0.0）。

## 五、执行计划

```
第1轮：优化精准度（优先）
  1a 阈值 0.45→0.55 + 1b top_k 7→5
  → 跑 RAGAS 子集，看精准度是否提升

第2轮：补召回（平衡）
  若精准度提升但召回下降太多 → 加查询扩展(2a)
  
第3轮：提忠实度
  temperature 0.1→0.0 + prompt约束
  
第4轮：全量验证
  232条跑 RAGAS，确认整体提升
```

**每次只改一个变量，用 RAGAS 子集（14条）快速验证**，达标后再全量。

## 七、优化执行记录

### 第1轮（2026-08-04）：提升精准度 ✅ 已完成

**改动**：
- RELEVANCE_THRESHOLD 0.45 → 0.55（过滤低相关chunk）
- RETRIEVAL_TOP_K 7 → 5（减少噪声chunk）
- LangChain引擎 query 方法加内容去重（hash去重，避免重复chunk）

**根因**：008 BM25 检索7条，仅1条相关，其余是毕业论文/医疗系统等噪声，score 0.48-0.53 过了0.45阈值。

**效果验证（RAGAS子集13条）**：
| 指标 | 优化前 | 优化后 | 变化 |
|------|--------|--------|------|
| 忠实度 | 0.635 | 0.645 | +0.01 |
| 答案相关性 | 0.833 | 0.832 | 持平 |
| 上下文精准度 | 0.316 | **0.43** | +0.114 |
| 上下文召回率 | 0.589 | **0.654** | +0.065 |
| RAGAS总分 | 0.593 | **0.64** | +0.047 |

**结论**：精准度+36%，召回同步提升（去重+聚焦反而帮助命中关键信息）。

**代码已提交**：`perf(retrieval): 检索结果去重`

### 第2轮（评估后决定）：查询扩展 — 谨慎使用
**评估结论**：查询扩展提升召回（001 RAG 从1文件变2文件），但：
- 对"知识库内容少"的用例无效（如004 DeepSeek，知识库本就少）
- 可能引入噪声（带出 test_ocr.png 等无关图片chunk）→ 精准度下降
- 精准度是当前瓶颈（0.43），引入噪声会恶化

**决策**：暂不启用查询扩展。专注提升精准度。

### 第3轮（2026-08-04）：提忠实度 ✅ 已完成（效果微弱）
**改动**：temperature 0.1 → 0.0（更保守，减少幻觉）

**效果验证（RAGAS子集13条）**：
| 指标 | 优化1后 | 优化3后 | 变化 |
|------|--------|---------|------|
| 忠实度 | 0.645 | 0.644 | 持平 |
| 答案相关性 | 0.832 | 0.852 | +0.02 |
| RAGAS总分 | 0.64 | 0.645 | +0.005 |

**结论**：temperature 0.0 提升微弱。忠实度瓶颈不在生成温度，而在检索上下文（检索缺信息则无法避免回答不完整）。

**核心判断**：RAG 系统瓶颈在检索不在生成。检索优化（第1轮）收益最大（+0.047），生成优化微弱（+0.005）。

**代码已提交**：`perf(generation): temperature 降到0.0减少幻觉`

### 第4轮（进行中）：Reranker 精排提升精准度
**改动**：
- 引擎新增 use_reranker 参数，检索后对 sources 用 bge-reranker-base 重排
- 修复 bge-reranker-base 模型权重缺失（下载约1.1GB完成）

**预期**：重排把相关chunk排前面，提升上下文精准度。

**待验证**：RAGAS 子集评测
